# Fifth Proof of Use: mikuproject

Checked on 2026-06-22.

## Purpose

This proof checks whether `mikuproject` can consume the standard
`miku-ms-office-core` release `.mjs` asset within its current browser/global and
CLI bundle shape.

The proof uses the locally staged post-`v0.5.0` patch-suffix release asset
candidate:

```text
src/vendor/miku-ms-office-core-0.5.0.1.mjs
src/vendor/miku-ms-office-core-0.5.0.1.mjs.map
```

The candidate is generated by
`TAG_NAME=v0.5.0.1 npm run prepare:release-assets`. As of 2026-06-22, it is not
yet published on GitHub Release. Replace it with the matching GitHub Release
asset after publication.

## Integration Shape

`mikuproject` vendors the `.mjs` asset and generates a product-local global
adapter during `build:js`:

```text
src/vendor/miku-ms-office-core-0.5.0.1.mjs
src/js/ms-office-core.js
```

The generated adapter assigns the transformed ESM namespace to:

```text
globalThis.__mikuprojectMsOfficeCore
```

`mikuproject-src.html`, generated HTML, CLI bundle source loading, and test
harnesses load `src/js/ms-office-core.js` before `src/js/excel-io-zip.js`.

## Scope

Only the async XLSX ZIP read path is moved to core:

```text
excel-io-zip.ts unpackZipAsync -> readZipPackageAsync
```

The proof injects the product-owned `DecompressionStream` raw-deflate helper
into `readZipPackageAsync`.

The synchronous `packZip` and `unpackZip` paths remain product-owned for now.
This keeps the current workbook output policy stable, including stored-only ZIP
writing, timestamp fields, and flag behavior.

## Why Not Replace Writing Yet

`mikuproject` ZIP writing is currently part of its XLSX workbook output
contract. The current core writer has its own reproducible Office package
policy, including fixed 1980 timestamps and UTF-8 flags. Before replacing
`mikuproject` `packZip`, core should expose an explicit policy that can preserve
or intentionally change product output behavior.
